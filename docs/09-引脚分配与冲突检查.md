# 09 · 引脚分配与冲突检查

最终工程的全板引脚预算表，以及实际发生过的引脚/外设冲突记录。**多外设项目应在写第一行代码前先画出这张表**——本项目正是在没有这张表的阶段被引脚冲突反复折磨（见文末冲突史）。

## 定时器预算

| 定时器 | 用途 | 关键配置 |
| --- | --- | --- |
| BFTM0 | 系统 1ms 时基 | 中断自增 `bftm0_ct`，非阻塞定时器的时基 |
| BFTM1 | 控制周期 | 1ms 中断，数 10 次 = 10ms 速度环周期 |
| MCTM0 | 电机 PWM | CH2=PB6（右）、CH3=PB8（左） |
| GPTM0 | 左编码器 | Decoder Mode 3 四倍频正交解码 |
| GPTM1 | 右编码器 | 同上 |
| SCTM0 | 超声波测脉宽 | 48 分频 → 1MHz 计数 |
| SCTM1 | 舵机 50Hz | CH0=PB3 |

选型依据见 [03 定时器家族与资源分配](03-定时器家族与资源分配.md)。

## 中断清单

| 中断 | 干什么 |
| --- | --- |
| BFTM0_IRQn | `bftm0_ct++`（1ms 时基） |
| BFTM1_IRQn | 10ms 一次 `Motor_UpdateSpeed()` |
| UART0_IRQn | TX 环形缓冲出队 + RX 状态机拼包 |
| USART1_IRQn | 同上（扫码枪） |
| I2C1_IRQn | （MPU-6050 阶段）硬件 I2C 主收发状态机 |

## 冲突史（实际发生过的）

| 冲突 | 现象 | 解法 |
| --- | --- | --- |
| GPTM1 编码器 PC11/PC12 ↔ OLED 软件 I2C PC11/PC12 | 两路同时驱动同一引脚：编码器读数异常、OLED 显示不稳 | 编码器迁 PA1/PA0；原占 PA1/PA0 的电机方向脚迁回 PC2/PC9 |
| 舵机早期占用多通道定时器 | 后期外设扩展时资源紧张 | 舵机降级迁移到 SCTM1 单通道（PB3） |
| I2C1 PB7/PB8 ↔ 左电机 PWM PB8 | 车上装不下 MPU-6050 | 未解决（项目搁置）；复活需重新规划 PWM 引脚 |

## 冲突检查方法

1. 开工前列**全板表**：每个引脚的模块、方向、复用功能、上下拉（即本文第一张表）；
2. 每引入一个新外设，先在表里找空位，找不到就先做全局调整、再写代码；
3. 特别注意 HT32 的 AFIO 复用是**引脚级**的（`AFIO_GPxConfig`），同一物理引脚被两个外设先后配置不会有任何编译期警告，只会在运行时互相打架；
4. 台架上单模块都正常、一集成就出诡问题时，第一 suspect 就是引脚/外设复用冲突。
