# 03 · 定时器家族与资源分配

HT32 系列的定时器分为 **BFTM / GPTM / MCTM / SCTM** 四类，能力与定位差异很大。中文资料里很少有人讲清楚"什么场景该用哪个"，本文以本项目（7 个定时器全部用上）的实际分配为例给出选型参考。具体规格（通道数、位宽、时钟源）以你所用电机的官方手册为准。

## 本项目的分配

| 定时器 | 类型 | 承担的任务 | 用到的能力 |
| --- | --- | --- | --- |
| BFTM0 | BFTM | 系统 1ms 时基 | 纯周期中断，`bftm0_ct++`（见 [05 非阻塞设计](05-非阻塞软定时器设计.md)） |
| BFTM1 | BFTM | 10ms 控制周期 | 纯周期中断，数 10 次触发一次 PID |
| MCTM0 | MCTM | 双电机 PWM | CH2=PB6（右）、CH3=PB8（左）；输出使能/禁止切换 |
| GPTM0 | GPTM | 左编码器 | 正交解码模式（Decoder Mode 3，四倍频） |
| GPTM1 | GPTM | 右编码器 | 同上 |
| SCTM0 | SCTM | 超声波回波计时 | 计数器直读（48 分频 → 1MHz，1 tick = 1μs） |
| SCTM1 | SCTM | 舵机 50Hz PWM | 单通道 PWM 输出（PB3） |

## 选型经验

### BFTM —— 只做"时间"，不占通道

BFTM 没有输出通道，就是纯计数器 + 中断。凡"每隔 X ms 干一次活"的需求（系统时基、控制周期、软件看门狗喂狗）都该丢给它，**不要用带 PWM 通道的定时器做纯时基**——那是拿外设预算换不来任何收益。

本项目两个 BFTM 一个 1ms 时基、一个控制周期，是整台车软件并发的地基。

### GPTM —— 正交解码是它的本职

编码器 A/B 相接 GPTM 的两个通道，一行配置进入硬件四倍频解码，CPU 零开销：

```c
TM_DecoderConfig(HT_GPTM0, TM_SMSEL_DECODER3,
                 TM_CHP_NONINVERTED, TM_CHP_NONINVERTED);
TM_Cmd(HT_GPTM0, ENABLE);
// 之后读数只需：TM_GetCounter(HT_GPTM0)
```

**反面教训**：本项目早期版本用外部中断数脉冲测速，高转速下中断频率过高导致计数丢失，速度读数完全失真；换 GPTM 硬件解码后问题彻底消失。经验：**能交给定时器硬件干的事，不要用中断干**。

另外注意计数器位宽有限，长距离里程不要依赖硬件计数器直读——本项目用"读增量 + 软件累加到 `int32_t`"的方式规避（见 `drivers/Motor/Motor.c` 的 `Read_LeftEncoder()`）。

### MCTM —— 电机 PWM 的正主

MCTM 面向电机控制：多通道 PWM、互补输出、刹车等。本项目用它出两路电机 PWM（CH2/CH3）。一个实用技巧：MCTM 的引脚可以动态切回普通 GPIO（`AFIO_FUN_GPIO`）并强制拉低（见 `drivers/MCTM0/MCTM0.c` 的 `CHx_DisablePWMOutput()`）——急停时比"占空比给 0"更干净，因为不依赖定时器继续运行。

### SCTM —— "一个通道就够"的场景都归它

舵机只需要 1 路 50Hz PWM、超声波只需要一个能 1μs 精度计数的计数器，SCTM 都轻松胜任。

**反面教训**：本项目早期把舵机挂在了通道更多的定时器上，后来给舵机让资源时才被迫迁移。结论：**给"单通道小需求"分配定时器时，从能力最弱的 SCTM 开始挑**，把 GPTM/MCTM 留给真正需要多通道/解码/互补的场景。

## 资源冲突：一个真实案例

台架上各模块单独都验证通过，一集成就出问题——排查发现是引脚复用冲突：

- OLED 软件 I2C 占用 **PC11/PC12**；
- 右编码器 GPTM1 原配置在 **PC11/PC12**（当初台架接线随手选的）。

两路同时驱动 PC11，表现为编码器读数异常、OLED 显示不稳。最终重新分配：

1. GPTM1 编码器迁到 **PA1/PA0**；
2. 原占用 PA1/PA0 的电机方向脚迁回 **PC2/PC9**；
3. 顺手把舵机从多通道定时器迁到 SCTM1/PB3。

三条迁移记录全部来自当时的调试备忘（`project/HT32F52352_SmartCar_PID/说明.txt`）。**根因是动手前没有画全板引脚预算表**——[09 引脚分配](09-引脚分配与冲突检查.md) 就是补上的那张表，建议任何多外设项目开写前先做这件事。

## 经验浓缩

1. 先盘需求（几路 PWM？要不要解码？几个纯定时？），再按 BFTM→SCTM→GPTM→MCTM 的顺序"由弱到强"分配；
2. 能用硬件解码/硬件计数的不用中断；
3. 引脚分配和定时器分配在写第一行代码之前就要锁定成表；
4. AFIO 复用可以运行时切换——它既是灵活性的来源（急停断 PWM），也是隐性冲突的来源（本文案例）。
